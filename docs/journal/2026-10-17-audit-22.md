# 2026-10-17: Adversarial audit of the rebuild

An audit of the rebuild recorded in [2026-10-17-rebuild-22.md](2026-10-17-rebuild-22.md),
done before the work was pushed. Scope, as requested in review:
- the semantic contract and the independence of the test oracle;

## Method

**[Fact]** Five complementary checks, each written to avoid reusing the implementation's
assumptions:

1. **A written contract first** ([docs/SEMANTICS.md](../SEMANTICS.md)). It defines terms,
   the position rule for parameters, values by kind, templates and operations. It gives
   wend's obligations as precise statements about a strict reference value `R(e, env)`,
   and ends with a table separating what holds *by construction* from what is only
   *tested*.
2. **An independent reference evaluator** (`tests/contract_test.py`), written from the
   contract alone:
   - it evaluates term trees strictly with pathlib;
   - it imports only wend's parameter declarations, never its expressions, normal form,
     matcher or compiler;
   - random terms are trees rather than chains, so nested joins and the head/non-head
     position rule are exercised;
   - values include hostile inputs: traversal strings, NUL, `bytes`, ints, `PathLike`
     objects, look-alike slashes.
3. **Exhaustive enumeration for matching** (`tests/match_exhaustive_test.py`). For ten
   families, including genuinely ambiguous ones, every binding in a small domain is
   rendered and grouped by path. Completeness, soundness and ambiguity reporting are then
   checked exactly, rather than by sampling.
4. **Adversarial unit tests** (`tests/security_test.py`): traversal through every
   parameter kind, formatted fields, segments that become dot segments, non-string
   values, literal joins, and symlinks out of a tree.
5. **Packaging and platform checks**:
   - the wheel built with `uv build`, installed into a clean venv without dev
     dependencies, with the demo and every example run against it;
   - the full suite run on Python 3.15 (beta 4) as well as 3.14.6.

**[Measured]** Coverage of the contract property: the reference evaluator yields a value in
32% of generated cases, which are checked for agreement. 10% are elimination-free terms,
checked for strictness both ways; the rest are rejections by one side or both. Both contract
properties (interpreter and compiled function) passed at 20,000 examples each. The committed
suite runs 1,500.

## Findings

| # | area | finding | severity | status |
|---|---|---|---|---|
| 1 | Polars | `resolve_frame` accepted NUL in head and sub-path columns that `render` rejects (found by the adversarial property on its first 3.15 run; it reproduced on 3.14) | correctness bug | **fixed**: NUL check on every path-position column |
| 2 | inference | names were tokenised with `\d`, which matches non-ASCII digits (`٣`); `int()` accepts them but formatting renders ASCII, so the inferred layout failed its own verification (`AssertionError`) | correctness bug | **fixed**: ASCII `[0-9]` wherever text is parsed as digits (inference, fast-path plans, spec parsing, markers) |
| 3 | inference | a path listed both as a file and as a directory (`["a", "a/b"]`) was silently dropped from the schema | correctness bug | **fixed**: `ValueError` |
| 4 | discovery | `glob` follows symlinked directories at segment positions, like `Path.glob`, so a link inside the tree can lead discovery outside the root | safety risk | **mitigated**: `glob` no longer follows symlinks below the expression's literal prefix unless `follow_symlinks=True` (owner decision below) |
| 5 | traversal | safety applies to *parameter bindings*; a `str` joined directly is a trusted literal with pathlib semantics (`root / "../../etc"`) | documentation risk | **documented** (README, MIGRATING) and pinned by a test |
| 6 | process | commits were signed with the session's SSH key, registered to Claude, while authored as the owner, so GitHub would show them as "Unverified" (this is what the platform stop hook detects) | process | **fixed**: signing disabled in the repository's local config; the stack is rebuilt unsigned |
| 7 | pickling | a used expression could not be pickled (exec-generated function in its cache) | correctness bug | fixed before the audit (`_Cached`) |

**[Fact]** No disagreement with the reference evaluator, and no matching completeness or
soundness failure, was found in the core algebra, the interpreter or the compiler.

## Generated code

**[Fact]** `compile()` uses `exec` on source built from the expression's structure. Every
piece of user data reaches the source only through `repr()`:
- literal text and format specs;
- parameter names, as dictionary keys.

Objects (Params, Fields, deferred heads, types) are passed through the function's namespace,
not as source text. `test_generated_code_is_injection_safe` checks this with quotes,
backslashes, newlines, braces and code-like strings in literals, names and specs.

**[Interpretation]** Expressions are built by the program, not from untrusted input, so
`exec` here is a code generator, not an evaluator of external text. The remaining risk would
be a future change that inlines a value without `repr()`; the injection test guards that
boundary.

## Tested versus established

**[Fact]** From docs/SEMANTICS.md §8:

- **Established by construction:**
  - matching and glob soundness: every result is re-rendered before it is returned;
  - compiled error behaviour equals the interpreter's: every fast-path exception re-runs it;
  - inference coverage: inference verifies each observed path and raises otherwise.
- **Argued:** the fast-path uniqueness argument, written in the contract.
- **Tested only:** the contract obligations (agreement, no spurious rejection,
  strictness); matching completeness; compiled successes; Polars equivalence on the
  supported subset.

**[Interpretation]** The reference evaluator is independent of the *implementation*,
because it shares no code or representation. It is not independent of the *decisions*: the
contract was written after the rebuild and encodes three choices that the original oracle
forced:
- structural elimination;
- non-strict evaluation;
- whole-segment interpolations joined like `/`.

Docs/SEMANTICS.md is therefore the document to review as the specification.

## Decisions for the owner

- **[Decided]** `glob` defaults to `follow_symlinks=False`: following is opt-in, and the
  docstring calls this a traversal policy, not a sandbox or race protection.
- **[Decision → review]** Commit signing is off for this repository's local config, so
  commits are unsigned rather than signed with a mismatched key. Verified badges under the
  owner's name would need the owner's own signing key.
- **[Proposal]** Make `docs/SEMANTICS.md` the reviewed specification, and require changes to
  it to come with matching changes to `tests/contract_test.py`.

## Residual risks

- **[Interpretation]** POSIX only. A segment containing `\` is valid on POSIX and becomes a
  separator on Windows.
- **[Fact]** Types with a custom `__format__` that produce `.` under an integer spec are
  rejected by the enforced facts, rather than accepted with a different suffix.
- **[Fact]** Dynamic format specs, `Text`-derived fields and deferred heads are covered by
  unit tests, not by the contract property.
- **[Measured]** Constructing an expression costs about 30 µs.

## Current State

- `docs/SEMANTICS.md` defines wend's terms, parameter positions, values by kind, template segments, operations and obligations against a strict reference value, and separates guarantees by construction from tested properties
- `tests/contract_test.py` evaluates random term trees with a reference evaluator that imports only `wend.Kind` and `wend.Param`, and checks agreement, absence of spurious rejection and strictness for both `render` and compiled functions
- `tests/match_exhaustive_test.py` enumerates every binding of ten expression families over small domains and checks `match_all` completeness, soundness, `AmbiguousMatchError` for ambiguous paths, and that the fast-path family has no ambiguous path
- `tests/security_test.py` checks traversal rejection for segment, sub-path and formatted positions, literal join semantics and head-parameter trust (`tests/fs_test.py` covers the symlink policy)
- `wend.frame` checks every path-position column for nulls and NUL characters before rendering (`_Lowering.string_col`, `src/wend/frame.py`)
- `wend.frame` raises an `ImportError` naming `wend[polars]` when Polars is not installed (`src/wend/frame.py`)
- `wend.infer` tokenises names with ASCII digit runs (`_RUN`, `src/wend/infer.py`) and raises `ValueError` for a path listed as both a file and a directory
- `glob` starts at the expression's literal prefix and, unless `follow_symlinks=True`, does not descend symlinked directories or classify links by their targets below it; `recurse_symlinks=True` follows links inside a `SubPath` with cycle detection (`src/wend/_fs.py`)
- 162 tests (93 test functions) pass on Python 3.14.6 and on Python 3.15.0b4, and pyright 1.1.408 reports 0 errors on `src/wend`
- The wheel built by `uv build` contains `wend/py.typed`, installs into a clean Python 3.14 environment, and runs `demo.py` and every script in `examples/` without Polars installed

## Missing

- No test property covers dynamic format specs, `Text`-derived fields or deferred heads — those constructs have unit tests only
- No Windows path semantics — a segment containing `\` renders unchanged
- No reviewed sign-off on `docs/SEMANTICS.md` as the specification

## Divergence

- `pyproject.toml` declares version 0.1.1 while the public API differs from the 0.1.1 release on PyPI, as listed in `docs/MIGRATING.md`
