# 2026-10-18: The documentation site

This entry covers the infrastructure of wend's documentation site, the first step of the
plan in issue #78. It records what the site is built with, how it is checked and
published, and what a spike measured before the choices were made.

Labels: **[Fact]**, **[Measured]**, **[Interpretation]**, **[Decision]**.

---

## Current State

- **[Fact]** `zensical.toml` configures the site, built with Zensical 0.0.71 from the
  Markdown pages in `docs/site/` into `site/`. It is served at
  https://lmmx.github.io/wend/.
- **[Fact]** `docs/site/reference/api/` holds one page per public module. Each page is a
  `::: wend.<module>` directive, rendered by mkdocstrings-python 2.0.9 (griffe 2.3.2).
  `docs/site/reference/api/wend.md` groups the package's exports under headings.
- **[Fact]** `docs/scripts/griffe_wend.py` removes, after griffe loads the package, the
  special methods that only implement object protocols (`__repr__`, `__eq__`,
  `__slots__`, ...), and keeps the operators that are API (`/`, `|`, `-`, `&`).
- **[Fact]** `docs/scripts/griffe_wend.py` also replaces griffe 2.3.2's builder for
  `ast.TemplateStr`. The original passes `in_joined_str` twice when a t-string sits inside
  another t-string's interpolation (`t"{Alt('', t'.{k}')}"`), so griffe logs an error and
  drops the value.
- **[Fact]** The `llmstxt` plugin writes `llms.txt`, `llms-full.txt` and a Markdown copy of
  each listed page at `<page>/index.md`, linked from the page's head.
- **[Fact]** `docs/scripts/check_site.py` (adapted from lmmx/chloro) checks nav coverage,
  internal links and anchors, the `llmstxt` descriptions against each page's front matter,
  and that every name in each public module's `__all__` has an entry in the API reference.
- **[Fact]** `docs/conftest.py` makes each page under `docs/site/` one pytest test: its
  `python` and `pycon` blocks run in order in one namespace, in a fresh temporary working
  directory, and `pycon` output must match. `uv run pytest docs` runs them; the default
  `uv run pytest` still collects only `tests/` (`testpaths`).
- **[Fact]** `.github/workflows/site.yml` (adapted from chloro's) builds with `--strict`,
  fails on any `griffe:` line in the build log, runs `check_site.py` and the examples,
  publishes master to the root of the `gh-pages` branch, and publishes each pull request
  from the repository to `gh-pages/pr-preview/pr-<number>/` with
  `rossjrw/pr-preview-action`.
- **[Fact]** `.just/docs.just` provides `docs-serve`, `docs-build` and `docs-check` with the
  same pinned toolchain as the workflow.

## Decisions

**[Decision]** The toolchain is pinned with `uv run --no-project --with ...` in the
workflow and the Justfile, as in chloro, rather than as a dependency group. The docs build
reads `src/` statically and needs neither wend nor its extras, so it stays out of the
project's dependencies and `uv.lock`.

**[Decision]** mkdocstrings is configured in `zensical.toml`, not in a `mkdocs.yml`.
Zensical 0.0.71 maps `[project.plugins.mkdocstrings]` onto its own mkdocstrings extension
and enables autorefs with it.

**[Decision]** The reference uses `filters = "public"`, the only filter setting that
follows `__all__`. A regular-expression filter showed names missing from `__all__`, such as
`conditions.guard` and `schema.owners_of`.

**[Decision]** Undocumented members are shown (`show_if_no_docstring = true`). 269 of the
441 public objects griffe sees have no docstring, among them `PathExpr.parent`,
`PathExpr.name` and `Match.path`; hiding them would hide most of the API.

**[Decision]** Examples on the site are tests, run with the docs build in CI. A fenced block
inside an HTML comment runs but is not shown, for setup such as creating the files an
example reads. While copying, the copy button leaves out a `pycon` block's prompts and
output (`[data-md-copying] .gp, .go` in `extra.css`), so a copied block runs as pasted.

**[Decision]** chloro's `deploy-actions` job is left out. wend's Pages has never been set to
GitHub Actions, so the job's `configure-pages` step would fail. Production goes to the
`gh-pages` branch from the first master run, and previews start once Pages serves that
branch.

## Measured

- **[Measured]** A clean build takes 2.2–2.5 s warm and 10 s cold, including downloading
  the toolchain into an empty uv cache. An incremental build takes 0.56 s.
- **[Measured]** `llms-full.txt` is 81 KB, most of it the API reference. Each object has a
  heading, its signature in a `python` fence and its docstring as prose.
- **[Measured]** griffe loads all 20 modules and the 48 exports of `wend.__all__` with no
  warnings and no unresolved aliases under Python 3.14.6.

## Missing

- **[Fact]** Many docstrings are written in reStructuredText style. Lists without a blank
  line before them collapse into one paragraph, `::` blocks stay literal, and the bare
  `>>>` lines in `Lens` render as quotes.
- **[Fact]** `wend.errors`, `wend.frame` and `wend.infer` have no `__all__`, so the
  reference shows every name without a leading underscore, such as `errors.show`.
- **[Fact]** The reference shows `PathExpr.head`, `PathExpr.parts` and the private base
  class `_Cached`.
- **[Fact]** The site has no logo, guides or concept pages yet; issue #78 lists the pages
  to come.
- **[Fact]** Links in docstrings written as `[name][wend.Name]` become plain text in the
  Markdown copies; links written as ordinary Markdown links survive as absolute URLs.
