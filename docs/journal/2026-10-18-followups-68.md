# 2026-10-18: Follow-ups after the 0.2 batch

This entry covers items 1–4 of issue #68. Each is a place where two of the
19 PRs met only when they landed. Item 5, the conditions probe on non-local
filesystems, is not covered here.

Labels: **[Fact]**, **[Measured]**, **[Interpretation]**, **[Decision]**.

---

## One `Cardinality`

**[Fact]** Inference (#46) and schemas (#52) each defined a `Cardinality`
enum with the same four UML values. #52's journal entry left them apart to
avoid a diamond dependency between the two PRs. `from_inferred` took
`optional` from the layout. For the upper bound it used "many whenever the
pattern has parameters", not the layout's `many`.

**[Decision]** `wend.schema.Cardinality` is the only type, and `wend.infer`
imports it:
- A schema entry declares the two bounds (`optional`, `many`), and an
  inferred layout observes the same two. `from_inferred` turns the
  observation into a declaration, so the declared type is the one both use.
- `wend.schema` already exported it in `__all__`.
- A module of its own was not needed. The enum is 20 lines, and `wend.infer`
  importing `wend.schema` makes no cycle, because `wend.schema` imports
  `wend.infer` only for type checking.
- `wend.infer.Cardinality` still works, and it is the same class.
- `Cardinality.of(optional=..., many=...)` builds the value for both
  `Entry.cardinality` and `Layout.cardinality` (`src/wend/schema.py`).

**[Decision]** `from_inferred` takes `many` from the layout. A templated name
seen once per directory, such as `runs/run_{run:d}/model-{model:d}.pt`, is
now declared exactly one. Before, it was `1..*`. A second model in a run is
now a too-many problem.

**[Measured]** Round trips on this container's trees. Each one infers, runs
`from_inferred` and `validate`, then runs `source()`, `exec` and `validate`
again. "Tightened" counts the templated layouts that are not `many`, whose
upper bound changed from `*` to 1.

| tree | layouts | tightened | result |

| `/usr/share/doc` | 110 | 85 | ok, both ways |

`/usr/share/{man,locale,i18n,X11,fonts}`, `/usr/lib/jvm` and this repository
are ok too. A Hypothesis variant of the schema round-trip test, run as a
scratch script, passed 1,500 random trees with empty directories.

**[Fact]** `/opt` found a bug from before this work. With `hidden = False`,
validation left hidden names out of an entry's matches. It still counted
every directory that matched the entry's parent, so a hidden directory
there was owed a match it could never have. Ignored directories had the
same problem. `/opt` has `.github` beside package directories, and its
inferred schema reported 4 missing paths on its own tree. Such directories
are now not counted either (`Tree._count`), which is what §12 already says.

**[Interpretation]** Exact upper bounds expose one remaining exception, now
written in §12. Inference never observes a symlinked directory. Validation
counts one as a match of a directory entry, and `test_symlinks_count_by_target_and_are_not_followed`
depends on that. The exception arises when a symlinked directory matches a
templated `dir` layout that is not `many`, in a directory that also holds an
observed path of that layout. That directory then holds two matches. No
real tree above has the shape, because `dir` layouts come only from empty
directories.

## NUL in the Polars lowering

**[Fact]** The Polars lowering of `with_stem` and `with_name` cannot meet a
NUL that `render` refuses:
- a literal stem or name with NUL is refused when the expression is built
  (#54);
- `render` checks every field's text in `format_field`, and the lowering
  checks it in `_Lowering.field`.

**[Fact]** A `wend.Text` built directly skipped the construction check. Its
pieces reach a path unchanged, so `render` and `resolve_frame` both returned
paths holding NUL. Three routes did this:
- `with_stem` on an unbound path;
- a `Text` spliced into a t-string;
- concatenating with another `Text`.

**[Decision]** `Text` checks its literal pieces when it is made, so both
refuse with the same `PathOperationError` before either runs. A NUL check
in the lowering alone would have made `resolve_frame` raise where `render`
returned a path, which breaks the contract of `wend.frame`. The gap was in
construction, which both share. A differential test checks NUL in each
column of every lowered deferred operation: `resolve_frame` raises the same
error type as `render` (`tests/frame_gaps_test.py`).

## `glob(ambiguous=)` for unions and queries

**[Decision]** A union's `glob` has `wend.glob`'s semantics. It takes the
same options, with the same rule for a parameter named like one. A path is
ambiguous in two cases, and each path gets one error for both:
- two alternatives find it;
- one alternative finds it under two readings.

Errors are reported in path order, before the first match. Each one lists
every reading as an `AltMatch`, as `PathUnion.match` does.

**[Decision]** The union checks the keyword rule once, against itself. It
then walks each alternative through `_fs._glob`, which skips the rule. The
union passes its own collecting callback as `ambiguous`. Through the public
`glob`, a parameter named `ambiguous` left free in one alternative would
then make every call raise.

**[Fact]** Two behaviour changes for unions:
- `"raise"` now raises before the first match. Before, it raised when the
  merged stream reached the path.
- Argument errors are raised by the call, as for an expression. Before,
  they came on the first iteration.

**[Decision]** `Query.glob` forwards `ambiguous=` to its source. It applies
the option to a `&` pattern's ambiguity as the stream reaches the path, as
`Lens.map` does. Reporting those in global path order would mean running
the pattern filters over every result before the first yield, and the query
would no longer stream.

## Objects as bindings in `Lens` and `Ledger.run`

**[Fact]** Both already passed their bindings through `_make_env`, so an
object worked at runtime. Only the `Mapping` annotations rejected one, for
type checkers. The signatures are now `mapping: Any = None`, as everywhere
else since #60, and the tests cover every kind of object
(`tests/bindings_test.py`).
