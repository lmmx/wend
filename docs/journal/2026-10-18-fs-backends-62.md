# 2026-10-18: Filesystem backends — a protocol for discovery, fsspec, and prefix listing

Work on [#34](https://github.com/lmmx/wend/issues/34), built on the walker of
[#42](https://github.com/lmmx/wend/pull/42) (ambiguity reporting, option keywords, symlink
policy). The issue asked for three things:
- a small filesystem protocol used by `glob`, `infer` and existence checks, with local and
  fsspec implementations;
- discovery on object stores that lists by the expression's literal prefix rather than
  directory by directory;
- a decision on URLs: heads (`Root("s3://bucket")`) or a binding convention.

Labels as in the earlier entries:
- **[Fact]**: checked against the code, a test, or a library's source;
- **[Measured]**: a timing or a count from a run;
- **[Interpretation]**: a reading of the facts;
- **[Decision]**: a choice made here, with its reason;
- **[Proposal]**: work left for later, not done here.

---

## 1. What discovery touched

**[Fact]** Before this work, discovery reached the local disk directly:
- `_fs.py` listed directories with `os.scandir` and identified them for cycle detection with
  `os.stat`;
- it classified paths with `os.path.isdir`, `os.path.islink`, `os.path.lexists` and
  `os.path.isfile`;
- `infer._observe` checked its source with `os.path.isdir` and walked it with `os.walk`.

`render`, `match` and `Lens` touch no filesystem, so they already worked for any path
namespace.

## 2. The protocol

**[Decision]** `wend.fs.FileSystem` has five methods (`src/wend/fs.py:61-112`):

| method | `LocalFS` | `FsspecFS` | used by |
|---|---|---|---|
| `scandir(path)` | `os.scandir`, sorted | `ls(detail=True)` | `glob` |
| `kind(path, follow_symlinks=)` | one `os.stat`/`os.lstat` | `info` | `glob`, `infer` |
| `dir_key(path)` | `(st_dev, st_ino)` | `None` | `glob` (`recurse_symlinks`) |
| `walk(top)` | `os.walk` | generic, over a view | `infer` |
| `subtree(path)` | itself | a per-walk view (section 4) | `glob`, `infer` |

The guidance for this work listed `lexists`, `isdir`, `isfile` and `islink`. Three choices
differ from it:

- **[Decision]** A single `kind()` returning `"file"`, `"dir"`, `"link"`, `"other"` or
  `None` replaces the four predicates. Each question the walker asks is then one call. The
  old walker made two stats where it needed a property of the unfollowed entry (`isdir`
  then `islink` for a literal directory, `islink` then `isfile` for `kind="file"`). On a
  store each predicate would be a request, while `kind()` is one `info`. `kind()` also maps
  onto the two stat results that #27's `_Probe` caches (section 7). An `exists` method was
  not added: it is `kind(path) is not None`.
- **[Decision]** `scandir` returns entries with `os.DirEntry`'s interface (`name`,
  `is_dir`, `is_file`, `is_symlink`; the `DirEntry` protocol, `src/wend/fs.py:48-58`). So
  `LocalFS.scandir` returns `os.DirEntry` objects unwrapped, at no per-entry cost.
- **[Decision]** `subtree(path)` gives the filesystem to use for one walk below a fixed
  prefix. The walker calls it once with the literal prefix, and then reads only the
  returned view (`src/wend/_fs.py:220`). `LocalFS` returns itself; `FsspecFS` returns a view
  that lists the subtree once or caches what it lists. The walker is therefore the same
  code for the local disk, a store listed directory by directory, and a store listed by
  prefix.

**[Decision]** `dir_key` distinguishes two cases:
- `None` means the filesystem has no identity to give (stores). The walker then descends
  such directories without a cycle check, and does not descend a symlink at all
  (`src/wend/_fs.py:277-283`).
- `OSError` means this directory cannot be identified (a local stat failure). The walker
  skips it, as before.

Returning `None` for both would have made `recurse_symlinks=True` skip every directory on a
store.

**[Decision]** `walk` is in the protocol, rather than written once over `scandir`, so that
`LocalFS.walk` is `os.walk` itself. `os.walk` skips a directory it cannot list instead of
reporting it as empty, and `infer(path, fs=LocalFS())` keeps that.

**[Fact]** Local behaviour is unchanged. The walker binds `fs.scandir`, `fs.kind` and
`fs.dir_key` to locals before walking. Every existing test passes unmodified, and the
glob-option test runs once more with `fs=LocalFS()` (`tests/keywords_test.py`).

## 3. Local performance

**[Measured]** `docs/journal/scripts/2026-10-18-local-glob-ab.py` was run on a 30,060-file
tree:
- the tree is 3 splits × 5 years × 12 months × 167 files;
- old and new source were run alternately in separate processes, three rounds each;
- each figure is the minimum of 7 timed runs, in ms, one per round.

| case | results | before (#42) | after |
|---|---|---|---|
| templated segments | 30,060 | 177.5, 188.3, 178.6 | 174.8, 172.3, 169.8 |
| templated segments, `kind="file"` | 30,060 | 368.3, 383.8, 364.1 | 295.7, 294.9, 298.3 |
| `SubPath` recursion (15 runs, 4 rounds) | 30,060 | 203.3, 201.8, 199.5, 208.1 | 203.8, 200.3, 203.3, 206.9 |
| literal prefix | 2,004 | 9.0, 8.8, 8.6 | 8.4, 8.5, 8.8 |

**[Interpretation]** Plain globbing and `SubPath` recursion are unchanged within noise.
`kind="file"` is about 20% faster, because one `lstat` per result replaces `islink` plus
`isfile`.

## 4. Listing on object stores

**[Fact]** `FsspecFS(fs, listing="flat")` is the default (`src/wend/fs.py:226-310`). Its
view (`_Subtree`, `src/wend/fs.py:336-431`) is filled by one `find(prefix, withdirs=True,
detail=True)`, where `prefix` is the expression's literal prefix:
- each key below the prefix is split into segments;
- every ancestor becomes a directory with that key's first segment as a listed entry;
- the walker then reads the view as it would read a disk.

Matching, the `kind` filter, render verification and ambiguity reporting are the walker's
own, so results are the same as a directory-by-directory walk by construction.
`listing="tree"` fills the same view lazily, one `ls` per directory the walk reaches. Either
way, a path whose parent has been listed is classified from that listing, without an `info`
request.

**[Fact]** In s3fs 2026.9.0, `S3FileSystem._find` without `maxdepth` makes one
`_lsdir(path, delimiter="")` call. That is a flat ListObjectsV2 listing, paginated by the
service. With `maxdepth` it calls fsspec's generic `_find`, which walks directory by
directory. fsspec's `MemoryFileSystem.find` (2026.9.0) is one pass over its store.

**[Measured]** `tests/fsspec_test.py` counts calls with `Counting`, a proxy around a
`MemoryFileSystem`. It counts `ls`, `find`, `walk`, `glob`, `info`, `isdir`, `isfile` and
`exists` made through it, and not the filesystem's internal calls, so a store's `find`
counts once. The fixture holds 357 keys `events/year=Y/month=MM/day=DD/part-0.parquet`
(2 years, 21 months, 357 days), plus 50 keys beside the prefix:

| walk | calls |
|---|---|
| `glob`, flat | `find("/lake/events")` only |
| `glob` with `year=2025` bound, flat | `find("/lake/events/year=2025")` only (153 results) |
| `glob`, tree | 381 `ls` (1 + 2 + 21 + 357 directories) and 1 `info` (the prefix) |
| `glob`, tree, `kind="file"` | the same 381 `ls` and 1 `info` |
| `infer("/lake/events")`, flat | `find` only |

**[Interpretation]** Without the view's cache, a tree walk with `kind="file"` would add one
`info` per result (357 more requests). On S3, the flat walk costs one request per 1,000 keys
below the prefix, against one per directory reached. This was not measured against S3,
since the work was done without network access to a store.

**[Decision]** The flat listing is not bounded by the expression's depth. `find(maxdepth=)`
would bound it on memory, but makes s3fs walk directory by directory (above). So a flat walk
reads every key below the literal prefix, including keys deeper than the expression reaches.
The `FsspecFS` docstring and README name `listing="tree"` for prefixes with many such keys.

**[Fact]** s3fs refuses to `find` a whole store (`ValueError("Cannot traverse all of
S3")`). A walk whose fixed prefix is the store's root (a templated bucket, as in
`Segment("bucket") / "data" / ...`) catches that one `ValueError` and lists level by level
(`src/wend/fs.py:355-362`). A `ValueError` from any other prefix propagates.

## 5. URLs: heads or bindings

**[Decision]** URLs use the binding convention. `wend.fs.url_to_fs(url)` wraps
`fsspec.core.url_to_fs` and returns a filesystem and a path in its namespace, which is bound
as a root:
- `"s3://bucket/data"` gives `(FsspecFS, "bucket/data")`;
- `"memory://data"` gives `(FsspecFS, "/data")`;
- a local path or `file://` URL gives `LocalFS`.

Heads, the normal form and `docs/SEMANTICS.md` are unchanged.

**[Interpretation]** `Root("s3://bucket")` is not done now, because it would change the
normal form's anchors:
- `Root` holds `"/"` or `"//"`, and every structural operation (`parent`, `relative_to`,
  `_combine`, `canonical`, the compiler) and the contract assume POSIX anchors.
- The contract says `render` equals eager pathlib, and pathlib reads `"s3://bucket/x"` as
  `s3:/bucket/x`. A URL head would therefore need its own anchor kind, specified in
  `SEMANTICS.md`, implemented in each of those operations and checked by the reference
  evaluator.

The binding convention needs none of that. Stores keep their own namespace (bucket-relative
keys), which is where fsspec already puts them.

**[Fact]** A bucket-style root binds through `_literal_expr` to a relative head with
literal segments. So `glob`'s fixed prefix for `Param("root") / ...` with
`root="bucket/data"` is `"." + bucket + data` = `bucket/data`, and a memory root `"/data"`
binds to `Root("/")` plus `data`. `tests/fsspec_test.py` walks the same tree with both
spellings (`/tree` and `tree`, which fsspec's memory filesystem treats as one path). It also
walks from the store root, where the walk starts at `"."`.

**[Decision]** A URL bound as a path renders as `memory:/x` or `s3:/bucket/x` and would find
nothing. `glob` refuses a fixed prefix whose first segment is one of the `FsspecFS`'s
protocols followed by `:`, naming `url_to_fs`, when called rather than when iterated
(`_check_root`, `src/wend/fs.py:455`). `infer(source, fs=...)` passes `source` to fsspec
unparsed, so `infer("memory://x", fs=fs)` works as given.

## 6. Symlinks and existence on stores

**[Decision]** Stores have no symlinks:
- no `FsspecFS` entry is a link;
- `follow_symlinks` and `recurse_symlinks` change nothing (a test runs a `SubPath` glob with
  both set and compares it with the local walk);
- `dir_key` is `None`.

**[Decision]** Directories on a store, in the same rules for `ls`, `find` and `info`:
- a directory is a prefix of some key, or an explicit marker: `makedirs` on the memory
  filesystem, or a key ending in `/`;
- a key ending in `/` is a directory whatever type the store reports. **[Fact]** s3fs's
  `_iterdir` sets `type: "file"` on every listed object, placeholders included;
- a key that is also a prefix of other keys is a directory, as fsspec's `info` reports it;
- `kind="dir"` matches implied and explicit directories alike;
- an empty directory exists only as a marker, and `infer` reports it as the local walk
  reports an empty directory;
- a directory holding only hidden entries is empty when `include_hidden=False`, on both
  sides (a test checks it).

**[Decision]** Keys with an empty, `.` or `..` segment (`a//b`, `a/./b`) are left out of
every listing, because no expression renders them.

**[Decision]** `FileNotFoundError`, `NotADirectoryError` and `PermissionError` from a store
read as absence, as a failed local `stat` does. Other errors propagate, so a dropped
connection does not look like an empty directory. The protocol's `kind` docstring states
this.

**[Decision]** `FsspecFS` refuses fsspec's own local filesystem and points to `LocalFS`.
**[Fact]** fsspec's `LocalFileSystem.info` types a symlink by its target when given a path,
but as `"other"` when given a `DirEntry` during `ls` (`fsspec/implementations/local.py:79-
112`). It also exposes no `(st_dev, st_ino)` identity, so `glob`'s link policy and cycle
detection could not be kept through it.

## 7. Existence checks in #27

**[Fact]** On `claude/conditions-27` (PR #49), `_Probe` (`src/wend/conditions.py:299-335`)
caches `os.stat` and `os.lstat` for one path:
- `FileNotFoundError` and `NotADirectoryError` read as missing;
- any other `OSError` raises `ConditionError` ("could not be checked");
- `Exists`, `Absent`, `File` and `Dir` read the two results;
- `Readable`, `Listable`, `Writable` and `Creatable` call `os.access`;
- `Under` calls `os.path.realpath`;
- `_ancestor` calls `os.path.exists`.

**[Proposal]** The wiring, after both branches merge:
- `_Probe(path, fs=LOCAL)` replaces `st` with `fs.kind(path)` and `lst` with
  `fs.kind(path, follow_symlinks=False)`;
- `Exists` is `st is not None` and `Absent` is `lst is None`;
- `File` is `st in (None, "file")`, since `kind` is `"file"` exactly when `S_ISREG`;
- `Dir` is `st in (None, "dir")`;
- `_ancestor` uses `fs.kind(parent) is not None`.

The capability conditions and `Under`'s realpath check have no protocol method and stay
`LocalFS`-only. They would raise a clear error on another filesystem.

**[Interpretation]** One semantic gap needs a choice at that point. `kind()` reads a path it
cannot examine (EACCES, ELOOP) as `None`, as `os.path.isdir` does and as the walker needs.
`_Probe` reports those as "could not be checked". Either the probe keeps `os.stat` for
`LocalFS` and uses `kind()` only for other filesystems, or the protocol grows a strict
variant. Stores already raise for failures other than absence or permission.

## 8. Other decisions

- **[Decision]** `infer(source, *, ..., fs=None)` adds one keyword. `_observe` takes `fs`,
  opens one view of the source, and checks and walks it through the protocol. With `fs` and
  an iterable source it raises `TypeError`. The rest of `infer` is unchanged. Two lines that
  `claude/infer-kinds-51` also edits will conflict trivially when merged: the import block
  and the `_observe(...)` call.
- **[Decision]** `fs` is a `glob` option under #42's keyword rule. A parameter named `fs` is
  bound through the mapping, and `fs=` without it raises `TypeError` when the expression has
  such a parameter (`tests/keywords_test.py`).
- **[Decision]** The new tests live in `tests/fsspec_test.py`, since `tests/fs_test.py`
  already holds the `glob` tests. fsspec is in the `test` dependency group, which CI
  installs (`uv sync --group test`, `.github/workflows/test.yml`), so the tests run in CI
  rather than skip. It is also the `wend[fsspec]` extra. `wend` and `wend.fs` import without
  it; `url_to_fs` raises `ImportError` naming the extra.

## Current State

- `wend.fs.FileSystem` declares `scandir`, `kind`, `dir_key`, `walk` and `subtree`, and `wend.fs.DirEntry` declares the `os.DirEntry` interface that `scandir` entries provide (`src/wend/fs.py:48-112`)
- `wend.fs.LocalFS` implements the protocol with `os.scandir`, one `os.stat`/`os.lstat` per `kind`, `(st_dev, st_ino)` for `dir_key`, and `os.walk` (`src/wend/fs.py:126-165`)
- `glob` takes `fs=` (default the local disk), computes the fixed prefix before iterating, and walks a `fs.subtree(prefix)` view (`src/wend/_fs.py:55-301`)
- `infer` takes `fs=` and reads a directory of that filesystem through one view (`src/wend/infer.py:517-570`)
- `wend.fs.FsspecFS` adapts an fsspec filesystem with `listing="flat"` (one `find` below the literal prefix) or `listing="tree"` (one `ls` per directory reached), classifying listed paths from their parents' listings (`src/wend/fs.py:226-431`)
- `wend.fs.url_to_fs` splits a URL into a `FileSystem` and a path in its namespace, giving `LocalFS` for local URLs (`src/wend/fs.py:433-452`)
- `glob` refuses a fixed prefix that begins with an `FsspecFS` protocol followed by `:` when called (`src/wend/fs.py:455`)
- `tests/fsspec_test.py` compares `glob` and `infer` on identical local and memory trees across 13 expressions, both listings, both root spellings, and 60 random trees
- `tests/fsspec_test.py` asserts one `find` for a flat walk and 381 `ls` plus 1 `info` for a tree walk on a 357-key partitioned fixture
- `examples/fsspec_memory.py` discovers, gap-checks and infers a partitioned dataset in fsspec's memory filesystem through `url_to_fs`
- 227 tests pass on Python 3.14.6 and 3.15.0b4; pyright reports 0 errors on `src`

## Missing

- `_Probe` on `claude/conditions-27` reads `os.stat` and `os.lstat` directly, not `FileSystem.kind`
- No head kind for URLs — `Root` anchors are `/` and `//` only
- No `maxdepth` bound on a flat listing — a flat walk reads every key below the literal prefix
- No measurement against a network object store — listing costs are counted on a memory filesystem proxy
