# 2026-10-18: Every observed path is covered by a layout of its kind

This entry covers issue #51. Before this change, inference could cover an
empty directory with a file layout, and the layouts' counts did not add up to
the observed paths.

Labels: **[Fact]**, **[Measured]**, **[Decision]**.

---

## The bug

**[Fact]** Some empty directories merged with non-empty ones of the same name
or skeleton:
- `apt/examples/` with `bison/examples/`;
- `run_3/` with `run_1/`.

When they did, `_flatten` only went into the merged rule's children, and the
empty directory's own path was dropped. It belonged to no layout. It counted
as covered only when a file layout's pattern happened to match its name, as
`{dir}/{name}` does.

**[Measured]** On this container's `/usr/share/doc` (1714 paths), 38 empty
directories were covered only by a file layout. The layout counts summed to
1676.

## Decisions

**[Decision]** A layout has one kind and is inferred from paths of that kind
only. A directory rule gives two things:
- a `dir` layout of its own pattern, for the member directories that are
  observed paths (`_Rule.listed`);
- the layouts of its children below that.

A file and a directory never share a layout, whatever names they share. Dir
layouts generalise through the same machinery as file layouts: merged
parents, digit runs and SubPath folds. So an empty `fixtures/` in every
sub-package becomes `src/pkg/{rel...}/fixtures` (dir).

**[Decision]** The partition is now checked, not just claimed. After folding,
`infer` asserts that the layouts' counts for each kind equal the observed
files and the observed directories.

`Schema.total` counts distinct observed paths:
- a repeated entry counts once;
- a root entry (`./`) does not count.

Before, `infer(["a", "a"])` gave a total of 2, with counts summing to 1.

**[Decision]** Kinds reach the query side without breaking existing calls:
- `Schema.match(path, kind=None)` takes `"file"`, `"dir"` or `None`, with the
  same values and message as `glob`'s `kind`. With `None`, a string ending in
  `/` is a directory, as in `infer`, and any other path matches either kind.
- `Schema.check` accepts `(path, is_dir)` pairs as well as plain paths.

## Results

**[Measured]** `/usr/share/doc` now has 110 layouts, up from 108:
- `{dir}/examples` (dir, 35 paths, 0..1) is new;
- `{dir}/html` (dir, 3 paths, 0..1) is new;
- kind-wrong paths fell from 38 to 0;
- the counts sum to 1714.

The other messy trees in `scripts/2026-10-17-messy-trees.py` are unchanged.

**[Measured]** Inference cost on `bench/bench.py` (20,030 paths) is within
noise. The `/usr/share/doc` walk is 4% slower, mostly because of the two extra
layouts.

**[Fact]** #52's schemas still round-trip on the real trees with every open PR
merged together (`from_inferred`, then `validate`, then `source`). That covers
`/usr/share/doc`, `terminfo`, `zoneinfo`, `/usr/lib/python3` and
`/usr/include`, now that dir layouts sit beside file layouts that also match
their names.

## Left open

- **Empty directories never form a directory map on their own.** They merge
  only by sharing a name or skeleton with non-empty siblings. So
  `/usr/share/doc`'s 12 empty top-level directories stay as 12 one-path dir
  layouts. An analogue of `{stem}.ext` for files would collapse them, but it
  changes inference beyond this issue.
- **One empty member stops opaque detection.** `_profile` returns `None` when
  a member directory has no children.
