# 2026-10-18: Directory schemas, declared and inferred

This entry covers issue #32. A project's layout is declared once, then bound,
validated and scaffolded, and an inferred layout becomes the same kind of
declaration. The rules are in [SEMANTICS.md §12](../SEMANTICS.md#12-schemas).

Labels: **[Fact]**, **[Measured]**, **[Interpretation]**, **[Proposal]**, **[Decision]**.

---

## What landed

**[Fact]** `wend.schema` has five parts:
- a `Tree` base class, whose subclasses declare entries with `File(path, ...)`
  and `Dir(path, ...)`;
- `validate`, which returns a `Report` of every problem;
- `scaffold`, an explicit effect;
- `from_inferred`, which turns `infer`'s result into a declaration;
- `Tree.source()`, which writes any schema as Python.

Part 1's `MLProject` is expressible almost exactly as the essay wrote it:

```python
class MLProject(Tree):
    data = Dir("data")
    raw = Dir(data / "raw")
    models = Dir("models")
    checkpoints = File(models / T(t"model-{index:03d}.pt"), many=True)
    config = File("config.yaml")
```

## Decisions

**[Decision]** The conditions `File` and `Dir` from #27 (§10) make entries
when called: `File("config.yaml")` reads like Part 1's `File["config.yaml"]`.
The issue offered three syntaxes: an annotated class, a dataclass or a
Pydantic model.
- Annotations would need `File` and `Dir` to be types, but they are values,
  so type checkers would reject them.
- A model adds a dependency for no gain.

Entries are descriptors with `__get__` overloads. `MLProject.config` is the
`Entry`, and `MLProject("/srv").config` is a `PathExpr`. pyright sees both
types. Part 2 complained that a dictionary of bindings "doesn't look that
great"; a class body of declarations does.

**[Decision]** A bound entry carries conditions. It requires its kind, and
also `Exists` when it is exactly one and literal. So `project.config / "x"` is
refused at construction (nothing is below a file), and
`project.config.check()` verifies the file. Schemas and conditions are one
model: a schema is a set of conditioned expressions under a common root.

**[Decision]** A schema declares the connectivity of Part 2 up front. An entry
built from another (`Dir(data / "raw")`) keeps the relation through binding:
`project.raw.base == project.data`, and `project.raw.rebase(project.data, ...)`
works. This answers the issue's third open question: a schema is a set of
related expressions with a shared base, and the relations are the #26
derivations.

**[Decision]** Cardinality uses #31's four UML values (`1`, `0..1`, `1..*`,
`0..*`), declared as two flags, `optional` and `many`. That settles the issue's
second open question, where Part 1's prose had four values and its enum three.
- Cardinality is counted **per directory matching the entry's parent**, the
  same definition #46 uses for inferred layouts. "Exactly one config per run"
  is `File(t"runs/{run}/config.json")`.
- The default is exactly one, the strictest choice, so a declaration states
  any looseness explicitly.

**[Decision]** Validation observes the tree **as `infer` does**, so that an
inferred schema validates its own tree. The round trip on real trees forced
three rules:
- **A symlink counts by its target, but is never followed.** zoneinfo and
  `/usr/share/doc` are full of symlinked files. Treating them as neither file
  nor directory, as `glob(kind=...)` does, made hundreds of them stray.
- **A symlinked directory is neither descended nor reported.** Inference
  never observes one, and Debian's doc tree has dozens (`cpp -> cpp-13-...`).
- **A directory holding nothing observable is not reported.**
  `/usr/include/clang/18.1.3` contains only a symlinked directory, so
  inference never sees it.

`hidden = False` mirrors inference's default of skipping dotfiles.
`from_inferred` sets it, and declared schemas look at everything unless told
otherwise.

**[Decision]** Report every problem, as data. The issue asked for "missing,
extra and misfiled paths with the layout each one violates":

| problem | meaning |
|---|---|
| missing | too few matches in some parent directory |
| too-many | more than one match where one was declared |
| wrong-kind | a path an entry of the other kind would match |
| misfiled | a stray path named like an entry's last segment |
| extra | anything else; only the topmost stray is reported, with the nearest directory entry above it |

Overlaps (paths two entries match) are listed but are not problems. Inferred
schemas overlap by design, for example `{dir}/{name}` beside a literal
`Kentucky/Louisville`.

**[Decision]** Scaffolding creates directories. It creates files only with
`files=True`, and then only empty, required ones, with `O_CREAT | O_EXCL`, so
it never overwrites. An entry with free parameters is created once per
combination of their declared `choices`, which is what a schema needs for
`data/{split}` with `split` in `{train, valid}`. Without choices it is
skipped, because there is nothing to create.

**[Decision]** `from_inferred` takes the lower bound from `optional`. It takes
the upper bound as "many" for any templated layout. That can never fail on the
source tree, but it is looser than the observation. #46's `Layout.many` gives
the exact upper bound; once #46 and this PR are both on master, `from_inferred`
should use it, and the two `Cardinality` enums should become one. The
duplication is deliberate for now, to avoid a diamond dependency between the
two PRs.

## Measurements

**[Measured]** Round trips: `infer(tree)`, then `from_inferred`, `validate`,
then `source()`, `exec` and `validate` again. Results on the container's trees:

| tree | layouts | result | time |
|---|---:|---|---:|
| `/usr/lib/python3` | 451 | ok, both ways | 7.1 s |
| `/usr/include` | 124 | ok | 1.1 s |
| `/etc` | 187 | ok | 0.3 s |
| `/usr/share/zoneinfo` | 13 | ok (176 overlaps) | 0.07 s |
| this repository | 45 | ok | 0.1 s |
| `/usr/share/doc` | 112 | 38 wrong-kind, filed as #51 | 2.2 s |

The `/usr/share/doc` failures are real findings. Inference counts empty
directories under a *file* layout (`{dir}/{name}`), because its coverage check
ignores kinds. Validation reports them correctly. #51 proposes kind-aware
coverage.

**[Measured]** The Hypothesis round trip over random trees passed 1,000
examples. A variant with empty directories passed 500. The suite runs 60.

## Open threads

**[Proposal]** Validation cost is dominated by one `glob` per entry, which is
about 7 s for 451 layouts. A single walk that matches every path against every
entry's per-segment plans, as inference's prefix frontiers do, would make it
one pass.

**[Interpretation]** A schema plus `Step` (#27) and lineage (#28) gives the
pipeline picture of Part 5:
- a step's inputs and outputs are schema entries;
- `validate` is the static check before running;
- `scaffold` is the setup effect.

The next connection is to let `Step` take entries directly.
