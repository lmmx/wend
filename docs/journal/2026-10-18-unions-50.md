# 2026-10-18: Unions, alternatives and queries

This entry covers issue #29: variants in a layout, fallback chains, and
filtered discovery. It records what landed and the decisions behind it, so the
next change to [SEMANTICS.md §11](../SEMANTICS.md#11-unions-and-queries)
starts from the reasons.

Labels: **[Fact]**, **[Measured]**, **[Interpretation]**, **[Proposal]**, **[Decision]**.

---

## What landed

**[Fact]** Three constructs, all built from existing parts:

- **Unions** (`a | b`, `U(a, b)`): an ordered set of expressions with
  - `match`, `match_all` and `glob`;
  - `renderings`;
  - `first`, the fallback;
  - every path operation, distributed over the alternatives.
- **`Alt(...)`** inside a t-string given to `U`: each option is spliced in as
  text, as a t-string or as a parameter, and the template expands to the
  product of its options. Log rotation is one pattern:
  `U(t"{d}/app.log{Alt('', t'.{k}')}{Alt('', '.gz')}")`.
- **Queries** (`wend.query`): a source pattern plus filters:
  - `q - x`, the difference by pattern;
  - `q & x`, the intersection by pattern, which merges bindings;
  - `q.where(...)`, with conditions from §10, filesystem predicates such as
    `modified_after` and `larger_than`, or callables.

  They are evaluated lazily as `glob` streams results.

## Decisions

**[Decision]** Alternation lives *outside* the normal form. A union is a
sequence of branch-free expressions, and `Alt` expands at construction time.
This resolves the tension the issue named:
- [Part 4](https://cog.spin.systems/future-paths-compilation-theory) wants
  paths as pure expressions "without branches", and they still are;
- every rule of §1–§10, the contract tests, the compiler and the fast matcher
  apply to each alternative unchanged;
- the union rules in §11 are stated entirely in terms of the alternatives'.

The cost is exponential expansion: `n` binary `Alt`s give `2ⁿ` alternatives.
It is capped at 4096, and realistic layouts use two or three.

**[Decision]** There is no pattern syntax. `Alt` is a Python object in an
interpolation, so t-strings still do all the parsing, as Part 4 argues they
should. Optional pieces are `Alt("", x)`, so no separate `Opt` construct is
needed.

**[Decision]** Unions are opt-in, never produced silently. `T`, `P`, names and
suffixes refuse `Alt` and union values with a message pointing to `U`. Only
`U`, `|`, and `/` with a union (or with a t-string holding `Alt`) return a
`PathUnion`. `PathExpr.__truediv__` has overloads, so a type checker sees
`PathExpr / PathUnion -> PathUnion` and everything else as `PathExpr`. Nothing
that type-checks today changes type.

**[Decision]** `render` is defined only for a union of one alternative. The
issue offered three options: the first alternative, an error, or not allowed.
Rendering the first alternative would pick silently between paths the user
declared equally valid, so it is an error that names `renderings` and `first`.

**[Decision]** `first` is the fallback and an explicit effect. It returns the
first alternative that exists *and* meets its own `requires` (§10), so
`(user | system | default).requires(File)` skips a directory where a file was
expected.

Every alternative must render. A missing binding is a programming error, not
a reason to skip an alternative, and skipping would hide it. If none
qualifies, `NoAlternativeError` (a `FileNotFoundError`) lists each path tried
and why it failed.

**[Decision]** Ambiguity across alternatives raises, as within one
expression. A path two alternatives read, or one alternative reads twice, is
ambiguous. The alternative behaviour would be priority: an ordered choice, as
in PEG or regex alternation. That would make overlaps silent and order
significant for matching, against §7's rule that wend does not choose between
readings. The log-rotation pattern shows how to stay unambiguous: with
`k: int`, `app.log.1.gz` has one reading, while an untyped `k` makes it
ambiguous and the test checks that it raises.

**[Decision]** Query filters are a conjunction, so wend reorders them by cost:
pattern filters, then callables, then filesystem predicates. This is the
"query planner" of Parts 1 and 2 in its smallest form. Reordering a
conjunction of side-effect-free tests cannot change the admitted set, and a
stat runs only for paths that the pure tests admit; a test checks the order.

`&` merges bindings and is strict. Two readings of the second pattern that both
agree with the bindings so far are an ambiguity error.

## Tests and measurements

**[Measured]** The union property checks that matching on a union reduces to
its alternatives'. It runs on random pairs of the contract's terms. At 5,000
examples:

| outcome | cases |
|---|---:|
| exactly one reading | 1,612 |
| several readings, raised as ambiguity | 80 |
| a rendering no reading can parse back (`True` for an `int` field) | 19 |
| skipped: not invertible | 1,631 |
| skipped: did not render | 2,625 |
| skipped: did not build | 1,414 |

The suite runs 400 examples. An Hypothesis property also checks `Alt` expansion
against direct substitution.

**[Fact]** The first version of `PathUnion.glob` tagged every result with the
*last* alternative. Generator expressions built in a list comprehension bind
the loop variable late. The log-rotation glob test caught it, and the fix moves
the tagging into a helper function.

## Open threads

**[Interpretation]** Effects overlap (#27's journal entry) needs pattern
intersection: whether two expressions can render the same path. Unions make
the need sharper: a union whose alternatives overlap is ambiguous on the
overlap, and today that is found only by matching a concrete path. A static
check, "these alternatives can never overlap", would let `U(...)` warn at
construction. For fixed-structure segments, the per-field forcing rules of the
fast matcher (§8) are the beginning of such an analysis.

**[Proposal]** `glob(ambiguous=...)` from #42 should apply to unions: skip or
report a path two alternatives find, instead of raising. This waits until #42
and this PR are both on master.

**[Proposal]** Query union (`q1 | q2`) and query-level `first` are natural
extensions. Neither is needed for the issue's acceptance criteria.
