# 2026-10-22: Evidence is not a path, and a check certifies only what it checked (research)

The audit of [the typed core](2026-10-22-typed-core.md) (its addendum, A.1–A.2) found two
places where the types claimed more than the checks. Both were confirmed in Pyright
1.1.407, in ty 0.0.90 and at runtime.

1. **Evidence survived a change of subject.** `Checked` and `Confirmed` subclassed
   `pathlib.Path`, and pathlib builds derived paths with the receiver's class. So
   `c.parent` and `c / ".." / ".."` were `Checked`, with the original atoms, statically
   and at runtime. A demand for `Checked[... Under["/srv/static"]]` accepted
   `ok / ".." / ".." / "etc" / "passwd"`.
2. **An entry check certified postconditions.** `Checked[C, K]` carried `C`, the whole
   declaration, with ensured atoms written `post_*`. The entry evidence of an output was
   typed as if `post_exists` had been checked, when the check had found the path
   absent.

The owner's decisions, and the principle the owner stated:
- checked events stop being paths;
- preconditions and postconditions are separated, in the semantics and statically;
- the representation is to be chosen by prototype;
- the principle: **evidence should not silently survive an operation that changes the
  subject of that evidence.**

This entry records the prototypes, the choice, the fix and its measurement. The
specification now states the result (SEMANTICS.md §10.2).

Labels as in the other entries: **[Proven]** under named assumptions, **[Measured]**,
**[Fact]**, **[Conjecture]**, **[Refuted]**, **[Interpretation]**.

---

## 1. Evidence objects

**[Fact]** `Checked[C, K]` and `Confirmed[Q, K]` (`wend._kinds`) are now objects that hold
evidence, not paths:
- `path`, the path the check was about, as an ordinary `pathlib.Path`;
- `atoms`, what the check found true;
- `epoch`, set when a `Run` made the evidence.

They have no path operations. `c.parent` is an attribute error for both checkers and at
runtime. A path derived from `c.path` is an ordinary path: the loss of the evidence is
visible in the code, as the owner asked (`checked.path.parent`).

**[Interpretation]** One operation is kept, `os.fspath(c)` (so `open(c)` works),
justified individually:
- it *uses* the path the evidence is about, unchanged, and derives nothing;
- its result is a `str`, which claims nothing.

No other path operation is kept, because each changes the subject.

**[Fact] The API.** `check()` and `confirm()` return a plain `Path` again, as in the
released 0.2.0, whose documentation shows `PosixPath(...)`. A plain path claims nothing,
so it is sound. The evidence comes from two new methods:
- `checked()`, returning a `Checked[C, K]` over what the expression *requires*;
- `confirmed()`, returning a `Confirmed[Q, K]` over what it *ensures*.

**[Measured]** #113's `Path` subclass had broken three documented examples:
- `docs/site/concepts/effects.md`;
- `quickstart.md`;
- `untrusted-input.md`.

Each shows `check()` returning `PosixPath(...)`, and `Checked`'s `repr` differs. The
docs' examples run only in the documentation workflow (`pytest docs`), not in
`uv run pytest`, so the stack's test suite never saw it. With this change all 19 pass
again.

If the owner prefers `check()` itself to return the evidence, as in the owner's sketch
`checked = path.check(); checked.path`, the change is one line per method. It would
break 0.2.0's documented `check()`, which is why it is not made here.

## 2. Separating what is required from what is ensured: two representations

The owner asked for the representation to be prototyped before every overload was
rewritten. He suggested that a separate step-transition type might express the Hoare
triple {P} step {Q} better than a second parameter on every expression. Both were
built as minimal models with identical uses (`experiments/typed_core/prepost/`).

- **A**, `model_a.py`: one expression type, `Expr[C, K, Q]`. `requires` adds to `C`,
  `ensures` adds to `Q`. Evidence: `checked() -> Checked[C, K]`,
  `confirmed() -> Confirmed[Q, K]`.
- **C**, `model_c.py`: `Expr[C, K]` carries only what is required. `ensures` returns
  `Ensured[C, K, Q]`, a subtype, the transition, and only it has `confirmed()`.

**[Measured]** Under both checkers the two behave identically on every use
(`uses_a.py`, `uses_c.py`). Both reject:
- an output's entry evidence where `exists` is demanded;
- an expression not declared a File;
- `checked().parent`;
- a missing atom;
- an input's confirmation;
- an entry check offered as a confirmation.

Both accept the valid uses, and both show ty's gap on the same two lines (§3).

**[Interpretation] The choice: A.**
- A's third parameter has a default, so every existing annotation keeps its meaning:
  `PathExpr[Literal["read"], IsFile]` still says "requires `read`, declared a File".
- A needs no runtime change. C needs `ensures` to return an instance of a new runtime
  subclass, or a static type that differs from the runtime class.
- The transition C wanted already exists one level up. The ports (`Uses`, `Holds`,
  `Makes`, `Commits`) are typed per step: what the step requires, and what it
  publishes or confirms.

With A, expressions carry the triple's two halves apart, and ports carry the step.

**[Fact]** In the core:
- `PathExpr[C, K, Q]`, with `Q` contravariant and defaulting to `Never`;
- `Condition[Pre, Post]`'s ensured atom is now the same plain atom as its required one
  (`Literal["exists"]`, not `Literal["post_exists"]`), because the phase is now the
  parameter;
- `requires`, `ensures`, `tag`, `bind`, `rebase` and `P` carry all three;
- `rebase` keeps `Under[str]` in each phase that declared some `Under`.

## 3. ty's precision gap, diagnosed

**[Measured]** The audit found that ty 0.0.90 dropped every atom of
`P("a").requires(Exists, Readable)`. That came from the catch-all overload
`requires(*conditions) -> PathExpr[C, K]`, which ty fell back to. The minimal model has
no catch-all, so the cause shows plainly (`prepost/tygap.py`):
- ty solves a method's type variables from the *expected* return type first;
- for an expected `E[Literal["exists", "read"]]` it fixes each condition's atom to the
  whole union;
- the invariant `Cond[Literal["exists"]]` then no longer fits.

Without an expected type, ty infers the call exactly. The overloads are not the cause:
one plain generic method shows the same thing.

**[Measured] Variance cannot fix it in this encoding.** The same calls with a covariant
condition parameter:

| condition parameter | Pyright | ty |
|---|---|---|
| invariant | sound and precise | sound; rejects a valid declaration under a multi-atom expected type |
| covariant | **accepts** a one-atom declaration where two are expected (unsound) | **accepts** one- and two-condition declarations where more are expected (unsound) |

So the encoding keeps invariance. This confirms #106 §4.3's reason, and qualifies its
"ty accepted none", which held only for single-atom demands. ty 0.0.90 cannot be both
sound and precise here; soundness was chosen.

**[Interpretation] The practical scope.**
- **Affected:** an expression written inline where a type naming two or more atoms is
  expected:
  - an annotated assignment with such a type;
  - an argument to a function that demands two atoms;
  - an inline port such as `Holds((P(root) / ...).requires(File, Exists, Readable))`.
- **Not affected:** a declaration bound to a name first, then used anywhere, which is
  how wend's examples and tests are written.
- **Workaround:** bind first.
- **Severity:** in ty the result is an error at the declaration, never a silent
  widening. `positive.py` keeps the one known case as `# E-ty:`.

**[Measured] ty's 103 deprecation warnings are gone.** The overload that rejects a join
below a File was `@deprecated`, and an untyped receiver matches every overload, so ty
warned at ordinary joins (101 in `tests/`, 2 in `src/`). The overload still returns
`JoinBelowFile`, which is not a path, and that alone rejects any use of the result.
`negative.py`'s join-below-a-File case is still rejected by both checkers.

## 4. Measured

**[Measured]** `experiments/typed_core/check.py`, both checkers:
- `negative.py` has an error on exactly its 19 marked lines. The 6 new ones are:
  - an entry check certifies no postcondition;
  - an exit check certifies no precondition;
  - evidence is not a path;
  - a path is not evidence;
  - a plain `check()` gives no evidence;
  - ensuring is not requiring (`Holds(P("a").ensures(File, Exists, Readable))`).
- `positive.py` has none, apart from the one known ty case.
- The prototypes and `tygap.py` match their markers.

**[Measured] The soundness harness, extended.** The audit found it blind to evidence and
to the phases. It now:
- compares required and ensured atoms separately;
- demands of every runtime-valid expression's `checked()` an atom it only ensures, and
  of its `confirmed()` an atom it only requires (all must fail);
- demands one atom it requires of `checked()` (must pass), and of `checked().path`
  (must fail);
- touches `checked().parent` (must fail).

Results at 400 programs, seed 1:

| | Pyright | ty |
|---|---|---|
| statements: exact / weaker / unsound | 1,416 / 38 / **0** | 1,416 / 38 / **0** |
| demands that must fail, accepted | **0** of 8,944 | **0** of 8,944 |
| demands that must pass, rejected | 0 of 871 | 0 of 871 |

The dead targeted chain the audit found (a bind, then a rebase that raised
`NotStaticError`) is replaced by one a rebase makes static and another moves. A second
new chain declares a base in both phases.

**[Measured] Cost against master.** Checker errors on code that exists on master changed
only by the known true positive (`conditions_test.py` passes the string `"Exists"` to
test the runtime's error). The other differences are in files the research branches
add, or are the same diagnostics printed with three type arguments.

**[Measured] Runtime against master.** Best of 5 per operation, second of two
alternating rounds; the first round was dominated by warm-up:

| | master | this branch |
|---|---|---|
| `construct` | 5.70 µs | 5.61 µs |
| `requires`, three conditions | 5.88 µs | 5.94 µs |
| `requires` and `ensures` | 8.55 µs | 8.92 µs |
| `render` | 4.30 µs | 4.29 µs |

`import wend` had medians of 34.9 and 36.4 ms over five runs each, within the runs'
spread (32.6–46.6 and 33.8–40.1 ms).

## 5. Found while building it

- **[Measured] `Any` made `rebase`'s overloads unreachable.** The first version wrote
  "whatever this phase declares" as `Any`. Pyright reported overloads 2 and 3 as never
  used: with `Any`, overload 1 covers them. `Never` says "requires nothing" under
  contravariance, does not overlap, and is what each overload now uses.
- **[Measured] A harness pitfall, again.** Tuple-unpacked type variables
  (`X1, X2 = TypeVar(...), TypeVar(...)`) are not recognised by Pyright: every atom read
  as `Unknown`. The first run of the prototypes therefore looked imprecise for a
  reason that had nothing to do with the encoding.
- **[Measured] The formatter wrapped two marked statements** in the prototypes and moved
  their markers, the pitfall #113 recorded. They are kept on one line.

## 6. What this changes elsewhere

- **The event, object and copy guarantees.** "It was true" now means: these atoms, of
  this path, at this moment, for what was required at entry or ensured at exit. Nothing
  derived from the path inherits it.
- **The audit's A.1 and A.2** in `2026-10-22-typed-core.md` are fixed here. The
  knowledge entry's "A static type can carry this faithfully" holds for the revised
  types, under the assumptions of §4's harness.
- **`Run`** builds `Checked`/`Confirmed` with their atoms and epoch as attributes, not in
  `__dict__`. `Run.known` reads `event.atoms` and `event.path`.

## 7. Open

- `PathUnion` is still not generic, so a union of expressions has no `C`, `K` or `Q`.
- **[Conjecture]** A ty release that falls back to solving without the expected type, as
  Pyright does, would close §3's gap without changing the encoding. `prepost/tygap.py` is
  the test case to rerun.
- Whether some operations on evidence could be justified to keep it is left open, for
  example a `Checked[..., IsFile]`'s `stat`, which would be a new check, not a derivation.
  None is provided.
