# 2026-10-22: Leases: what a read lease excludes, and who hears of a break (research)

The synthesis (§4.2) found that a read lease excludes the writer no observer can see, and
reclassified "a coherent snapshot of files others write in place" from impossible to
possible by exclusion. The owner asked for that result to be tested before anything rests
on it:

> test acquisition refusal, pre-existing writable mappings, concurrent writers, lease
> breaks, signals, abnormal exits, multiple inputs, shared fds, and unrelated
> application signal handlers

> Avoid changing process-wide signal handling in a general-purpose library. If the Linux
> mechanism requires signal behaviour that cannot be encapsulated safely, document that
> as an architectural limitation

and to establish whether, and under what conditions,

> The bytes copied into a sealed snapshot came from one stable file version throughout
> acquisition.

**The answers, in brief.**

1. **It holds, under conditions narrower than the synthesis stated** (§4, proposition L).
   - Opening a file with `O_RDONLY | O_TRUNC` empties it and leaves a read lease intact
     (§3.1). The synthesis's assumption L1, "any … truncation breaks it", is refuted for
     this case.
   - A size recorded with the leases repairs it: under an unbroken lease the size can
     only fall, to zero, so an unchanged size rules the truncation out.
   - The kernel also grants leases on files that change with no writer at all (`/proc`,
     §3.4). `Leases` now refuses every filesystem it has not tested.
2. **In-process leases cannot be made signal-free; leases taken by a helper can** (§3.2,
   §3.3).
   - `F_SETLEASE` makes its caller the owner of the open file description. A break is
     then a signal to the caller's process, whatever was arranged before.
   - The previous `Leases` cleared the owner just after taking the lease. A writer in
     between signalled the host, and a test that puts one there catches it.
   - Now a helper process takes the leases and exits. They stay on the descriptions the
     host holds, owned by a process that no longer exists, so no break signals anyone.
   - What remains process-wide: one `SIGCHLD` per acquisition, as for any subprocess,
     and the need to start an interpreter (§6).
3. **Leases need ownership, not privilege.** An ordinary user leases their own files
   (`test_only_the_owner_or_CAP_LEASE_may_lease`). The synthesis called it privilege.

Code:
- `src/wend/_experimental/fresh.py`: `Leases` (helper, sizes, `LEASABLE`), `Unleasable`;
- `src/wend/_experimental/events.py`: `Run(lease=True)`, which now leases every held input
  at once;
- `tests/leases_test.py` (33 tests);
- `experiments/mutation/mutants.py`, the committed mutation harness (§5).

## 1. Read leases, as the kernel implements them

**[Fact]** The source of Linux 6.18 (`fs/locks.c`, `fs/open.c`, `fs/namei.c`,
`fs/fcntl.c`):

- **Grant.** `check_conflicting_open` refuses a read lease with `EAGAIN` while
  `inode_is_open_for_write`. That counts every open file description with write access
  to the inode, including one kept alive only by a shared writable mapping.
  `generic_add_lease` checks again after inserting the lease, behind a full barrier: "It's
  possible for another open to race in after we did the earlier check for a conflicting
  open but before the lease was inserted."
- **Break on open.** `do_dentry_open` calls `break_lease(inode, f->f_flags)`.
  `__break_lease` decides by the access mode alone: `want_write = (mode & O_ACCMODE) !=
  O_RDONLY`. A read request does not conflict with a read lease.
- **Break on `truncate(2)`.** `vfs_truncate` calls `break_lease(inode, O_WRONLY)`, with the
  comment "Make sure that there are no leases."
- **Truncation by `open`.** `handle_truncate`, which performs `O_TRUNC` after the open,
  takes write access and truncates. It does not call `break_lease`.
- **Owner.** `lease_setup` calls `__f_setown(filp, task_pid(current), PIDTYPE_TGID, 0)`.
  Taking a lease makes the caller's *process* the owner of the description, overwriting
  any earlier `F_SETOWN`.
- **Announcement.** A break calls `kill_fasync`, then `send_sigio(fown, …)`. With no owner
  pid it sends nothing (`if (!pid) goto out_unlock_fown`). Otherwise it signals the tasks
  of that `struct pid`, with `F_SETSIG`'s signal, or `SIGIO` if none.
- **Breaking.** While a break is pending, `F_GETLEASE` reports the lease's target, `F_UNLCK`
  for a read lease. After `lease-break-time` (45 s here) the kernel removes the lease.

**[Fact]** `F_SETLEASE(2const)` says the holder is notified "when the file is opened for
writing or is truncated". The source above does not do that for the truncation an
`O_RDONLY` open performs.

## 2. The previous implementation

`fresh.Leases`, as the synthesis left it, did this for each descriptor in this process:
1. `F_SETSIG` to `SIGURG`, a signal whose default is to ignore;
2. `F_SETLEASE`;
3. `F_SETOWN` 0, so that later breaks announce to no one.

`unbroken()` asked `F_GETLEASE` alone. `Run(lease=True)` leased each held input on its
own, as it opened it.

## 3. Findings, in the order found

### 3.1 `O_RDONLY | O_TRUNC` empties a leased file and the lease does not know

**[Measured]** On ext4 and on tmpfs:
- a process with write permission opens a leased file `O_RDONLY | O_TRUNC`, blocking or not;
- the open succeeds at once and the file's size is 0;
- `F_GETLEASE` on the holder's descriptor still reports `F_RDLCK`, and `/proc/locks` lists
  the lease.

The probe is kept as
`test_opening_read_only_with_O_TRUNC_empties_the_file_and_keeps_the_lease`. The source
reading of §1 explains it: the open is a read request, and the truncation after it does
not ask.

**[Refuted]** The synthesis's L1, "any later open for writing or truncation breaks it",
is false for this truncation. So is the claim it supported. The two-file counterexample,
in `test_a_leased_collect_is_not_fooled_by_two_truncations`:
1. `collect` leases `a` and `b`, and copies `a`;
2. another process opens `a`, then `b`, with `O_RDONLY | O_TRUNC`;
3. `collect` copies `b`, which is now empty.

Both leases are unbroken. The copies are `a` as it was and `b` emptied. `a` was emptied
before `b` was, so no instant had both. A torn copy is also possible: a `pread` of the
recorded size that a truncation overtakes returns a prefix.

**[Proven] The repair.** Under an unbroken lease a file's size can change only one way.
- Every other change of size needs write access, or `truncate(2)` (§1, §4 L3), and each
  breaks the lease.
- `O_TRUNC` sets it to 0.

So the size never rises while the lease holds, and falls at most once, to zero. If it is
the same at two moments, no truncation emptied the file between them, unless it was
already empty, when truncation changes no byte. `Leases` records each size once the leases
are taken, and `unbroken()` asks for both conditions: every lease still `F_RDLCK`, and
every size unchanged.

**[Measured]** With the repair, the counterexample is rejected (`coherent is False`), and
so is a `Run` step whose input is emptied after the step has read it all
(`test_a_run_sees_its_input_emptied_only_through_the_lease`). In that test, without the
lease the step publishes, because the bytes it used were the bytes observed at entry. Only
the lease's size sees the input change during the step.

**[Interpretation]** The repair detects the truncation. It does not prevent it. Nothing
available to an unprivileged process prevents it: `FS_IMMUTABLE_FL` needs
`CAP_LINUX_IMMUTABLE`, and fs-verity is permanent and unavailable here. Whether this is a
kernel defect or a documentation gap is for the kernel's maintainers. No report has been
made: that is an outward-facing step for the owner to decide.

### 3.2 A lease taken in-process makes its breaks the host's signals

**[Measured]** In a host process (`test_a_lease_taken_in_process_makes_its_breaks_this_process_s_signals`):
- `F_SETOWN` 0, then `F_SETLEASE`, then `F_GETOWN` reads the host's own pid: the lease
  reset the owner, as `lease_setup` says;
- with `F_SETSIG` set to `SIGURG`, a writer arriving before the owner is cleared again
  runs the host's own `SIGURG` handler;
- with no `F_SETSIG`, the same writer ends the host with `SIGIO`.

**[Proven]** No order of calls in one process closes the window:
- the owner is set *by* `F_SETLEASE`, so no earlier call can prevent it;
- the owner is the thread group (`PIDTYPE_TGID`), so the signal is process-directed. Any
  thread that does not block it can take it, and a library cannot set every thread's
  mask;
- any signal `F_SETSIG` names is a signal some host handles:
  - `SIGURG`: the Go runtime preempts goroutines with it (a Go library loaded through
    cgo);
  - `SIGWINCH`: terminals and readline;
  - `SIGCHLD`: child reapers, asyncio's among them;
  - real-time signals: their default action ends the process.

**[Refuted]** The synthesis said `Leases` "sends it to no one" and that "a library must not
leave a process exposed to a signal it did not ask for". The aim was right, and the code
fell short of it: between steps 2 and 3 of §2, any break signalled the host.
`test_no_moment_of_taking_the_leases_lets_a_break_signal_the_host` puts a writer at
exactly that moment, wherever the host takes a lease. A mutant restoring the previous code
fails it (§5).

When the very first leased test was written, before `F_SETSIG`, a break killed pytest
silently (synthesis §4.2). The mutant "taken in this process" reproduces that today. The
first break in pytest's own process ends the run with `SIGIO`, which the harness counts as
a kill of a kind no test can report.

### 3.3 Leases taken by a helper that exits

**[Measured]** The design that encapsulates the signal:
1. The host opens each input read-only, as before.
2. A helper is started with `sys.executable -I -S -c …`, with the descriptors passed by
   inheritance (`pass_fds`). They are the same open file descriptions, not reopened files.
3. The helper sets `SIGIO` to ignored and `F_SETSIG` to 0. It then takes every lease,
   giving back those it took if one is refused, prints `ok` or the refused descriptor and
   errno, and exits.
4. The leases stay on the descriptions, which the host still holds. Their owner is the
   helper's `struct pid`, which has no tasks. `F_GETOWN` in the host reads 0.
5. The host reads breaks with `F_GETLEASE` and releases with `F_SETLEASE F_UNLCK`. Neither
   sets an owner: only adding a lease does.

**[Measured]** No break signals the host (`test_no_signal_of_a_break_reaches_the_host`):
- with the host's `SIGIO` at its default action, a non-blocking writer, a blocking writer
  and the release all happen, and the host survives to report;
- with handlers on `SIGIO`, `SIGURG`, `SIGWINCH`, `SIGRTMIN` and `SIGRTMAX`, none runs;
- every signal disposition is the same afterwards;
- the only handler that runs is `SIGCHLD`'s: one for the helper, one for the test's own
  writer process.

In the worst-moment test, the host never takes a lease itself.

**[Fact]** Why a dead owner is safe: `send_sigio` signals the tasks of the `struct pid`
the description holds a reference to. Once the helper is reaped, that `struct pid` has
none. A new process given the same number gets a new `struct pid`. **[Conjecture]** for
want of a test: forcing pid reuse needs `ns_last_pid` or wrapping the pid space.

**[Measured]** Costs:
- acquisition takes a median 14.7 ms for one file (p90 18.3) and 17.5 ms for eight
  (p90 19.1), on 4 CPUs with Python 3.14;
- the in-process acquisition it replaces took microseconds.

**[Measured]** The helper's report travels by pipe, not by exit status. So a host that
ignores `SIGCHLD` (children reaped unseen), or reaps every child with `waitpid(-1)`, still
gets its leases (`test_a_host_that_reaps_every_child_still_gets_its_leases`).

**[Fact]** The helper has the host's uid. Across `execve` it keeps only the host's
*ambient* capabilities (`capabilities(7)`). Root keeps `CAP_LEASE`. A non-root host given
`CAP_LEASE` in its effective set, but not as ambient, would lose it in the helper.
Untested.

### 3.4 The kernel leases files that change with no writer

**[Measured]** A read lease on `/proc/uptime` is granted (as on `/proc/self/status` and
`/sys` files). Its contents differ 50 ms later, the lease is still `F_RDLCK`, and its size
is always 0 (`test_the_kernel_leases_a_proc_file_that_changes_under_the_lease`). A lease
excludes *writers through open file descriptions*. It does not exclude a filesystem
that makes up its contents, nor one whose contents change beneath it:
- an NFS, SMB or FUSE server;
- an overlay's lower layers, changed directly;
- a block device written underneath.

`Leases` now refuses, with `Unleasable` (`EINVAL`), every filesystem outside `LEASABLE`:
ext2/3/4 and tmpfs, the two tested. xfs and btrfs very probably behave as ext4
(**[Conjecture]**: generic leases, and every write path checked in §4 L3 is in the VFS),
but they are refused until tested. Overlayfs is refused on principle.

### 3.5 A lease belongs to an open file description

**[Measured]** (`test_a_lease_belongs_to_the_open_file_description`):
- a `dup` of a leased descriptor shares the lease, and a release through either gives it
  up for both;
- a lease never released outlives the descriptor it was taken through, as long as a
  duplicate is open. It ends when the last one is closed.

**[Fact]** Until then, the first writer to arrive waits `lease-break-time` for a release
that no one will make. `Leases.release` must be called, and called before the descriptors
are closed: a closed number can be reused, and an `F_UNLCK` would then reach another file.
`Run` and `collect` release in `finally`, before closing.

### 3.6 Smaller facts, each measured

| what | result |
|---|---|
| a lease on a descriptor open `O_RDWR` | refused, `EAGAIN`: its own write access is a writer |
| the host itself holding the file `O_RDWR` | refused, `Busy` |
| two read leases on one file, through two descriptions | both granted |
| `F_UNLCK` where there is no lease | `EAGAIN`; `release` ignores it |
| rename over the name, unlink of the name | not breaks; the held object's bytes unchanged |
| open for writing through another hard link | a break: the lease is on the inode |
| `utime`, `chmod` | not breaks; no byte changes |
| a leaseholder process that exits, or is killed, without releasing | its leases end with it; a blocking writer then opens in under 1 s |
| a helper killed after taking one of two leases | `Unleasable`; no lease left on either file |
| a helper that cannot start | `Unleasable`; no lease |

## 4. Proposition L: a leased copy is one version

**Statement.** Let *F* be a set of regular files. For each *f* in *F*, let *d_f* be a
read-only open file description of *f*, on a filesystem in `LEASABLE`. Suppose:
- read leases are granted on every *d_f*, all of them, by *t₀*;
- each size *s_f* is recorded at *t₁ ≥ t₀*;
- at *t₂ ≥ t₁*, for every *f*, `F_GETLEASE(d_f) = F_RDLCK` and the size through *d_f* is
  *s_f*.

Then every *f*'s contents are constant on [*t₁*, *t₂*]. Bytes read through *d_f* in that
interval are *f*'s contents at *t₁*, and the copies of all of *F* are the state of *F* at
the one instant *t₁*.

**Assumptions.**
- **L1, grant.** A read lease is granted only if no description of the inode has write
  access, with no race against a concurrent open. *[Fact]* from the source (§1);
  *[Measured]* for descriptors, mappings and the host's own descriptor.
- **L2, break.** An open with a writing access mode, and `truncate(2)`, break every read
  lease before the opener can write. A lease that has begun to break never reads
  `F_RDLCK` on that description again. *[Fact]*, *[Measured]*.
- **L3, the ways contents change.** On a filesystem in `LEASABLE`, a file's contents
  change only:
  - (a) through a description with write access: `write`, a shared writable mapping,
    `ftruncate`, `fallocate`, `copy_file_range` or `splice` into it;
  - (b) by `truncate(2)`;
  - (c) by `open` with `O_TRUNC`.

  *[Measured]* for the calls listed: each refuses a read-only description
  (`test_every_other_way_to_change_the_bytes_needs_write_access`). *[Fact]* for
  `FIDEDUPERANGE`, which needs only write permission but shares extents only after
  comparing them equal: it changes no byte. That the list is complete is a
  **[Conjecture]**: it is every content-changing call known to this research, not an
  enumeration of the kernel.
- **L4, beneath the filesystem.** Nothing changes the storage except through the
  filesystem: no block device written underneath, no hypervisor, no server. *Assumed*. It
  is the reason for `LEASABLE`.
- **L5, the holder.** It does not take a lease on *d_f* again between *t₀* and *t₂*, and
  does not truncate *f* itself. *By construction*: `Leases` takes once.

**Proof.** Suppose *f*'s contents change at some *t* in [*t₁*, *t₂*]. By L3 the change is
of kind (a), (b) or (c).
- **(a), or (c) with a writing access mode.** It needs a description with write access
  at *t*. By L1, none existed at *t₀*, so one was opened in (*t₀*, *t*]. By L2 that open
  broke the lease, which then never reads `F_RDLCK` again (L2, L5). That contradicts
  `F_GETLEASE(d_f) = F_RDLCK` at *t₂*.
- **(b).** It breaks the lease (L2); the same contradiction.
- **(c) with `O_RDONLY`.** It sets the size to 0. Only kinds (a), (b) and writing-mode
  (c) could raise it again, and they are excluded as above, so the size at *t₂* is 0. It
  equals *s_f*, so *s_f* = 0. Then *f* was empty at *t₁* and stays empty: no byte changed.

So no change occurs in [*t₁*, *t₂*]. ∎

**Classification.** **[Proven]** under L1–L5. L1 and L2 are read from the source and
tested. L3 is tested for the calls named, and conjectured complete. L4 is assumed, and
`LEASABLE` keeps the filesystems where it fails out.

**The owner's question.** "The bytes copied into a sealed snapshot came from one stable
file version throughout acquisition":
- **Holds** for a `Sealed` copy made in a `Run(lease=True)` step that exits normally, and
  for `collect(observer="lease")` when it returns `coherent`. Both require `unbroken()` after
  the last read, under L3–L4.
- **Did not hold** for the previous implementation against `O_RDONLY | O_TRUNC` (§3.1).
- **Does not hold** without a lease. The synthesis measured 244 of 300 reads torn under a
  mapped writer. `test_a_leased_copy_is_one_version_and_an_unleased_one_need_not_be`
  repeats the control: page-by-page copies against a writer rewriting a 64-page file tear
  without leases, and never with them.
- **Is about objects, not names.** A rename or unlink does not break a lease (§3.6).
  `collect` checks names once more at the end. Whether a name changed and changed back
  is visible, through the directory's `ctime`, is still open (synthesis §8).

**[Measured]** The stress test, for completeness:
- in 1 s without leases, copies tore;
- in 3 s with leases:
  - the writer was held off (its non-blocking opens failed) and still wrote versions;
  - at least 5 copies ended with their leases unbroken;
  - no copy tore, whether its lease ended unbroken or broken. A writer held off writes
    nothing, so a broken lease marks a copy as unsafe to rely on, never as mixed.

## 6. The architectural limitation

The owner's condition was to document it "if the Linux mechanism requires signal
behaviour that cannot be encapsulated safely".

- **In one process, it cannot be encapsulated** (§3.2). A general-purpose library must
  not take leases in the host's process.
- **In a helper process, it can be**, at these costs, all of which the library imposes on
  its host:
  - **a process per acquisition**, about 15 ms. A host forbidden to spawn (a seccomp
    sandbox, an embedded interpreter with no `sys.executable`) gets `Unleasable`;
  - **one `SIGCHLD` per acquisition**, as for any subprocess. A host whose `SIGCHLD`
    handler assumes it started every child may be surprised;
  - **credentials across `execve`**: only ambient capabilities reach the helper;
  - **a writer delayed, at most `lease-break-time`**, while a step holds its inputs.

**Alternatives not taken:**
- **A persistent helper**, one per run, receiving descriptors over a socket
  (`SCM_RIGHTS`). It would cost about 15 ms once, and one `SIGCHLD` at its end. It would
  also need its own lifecycle: parent death, forked hosts, `PR_SET_PDEATHSIG`'s
  thread-of-creation trap. It is the obvious next step if the cost matters.
- **`clone` with no exit signal.** It would avoid `SIGCHLD` but needs raw `clone` from
  Python, which is unsafe in a threaded host.
